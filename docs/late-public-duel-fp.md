公開決闘の説明、結果の増減・加算前FP、版別ルールガイドも同じ実報酬と一致させた。既存の夜間UIには変更なし。

## 保存互換性・比較対象

新規ゲームはbrowser-2.0.4、保存枠は `majoken-save-rules-2.0.4`。旧v2.0.3は元の保存枠を維持し、「旧v2.0.3の続きから」も追加した。保存形式version 2と既存フィールドを維持し、変換や必須フィールド追加なし。

旧版は全日＋1FPのまま再開・再保存・再読込できる。新ルールを既存セーブへ途中適用しない。v2.0.3とv2.0.4は同じNPC属性選択AIを使い、v2.0.2以前のAI分岐も保持する。AI評価式・戦略・乱数関数は変更していない。報酬が変わった後のFPをAIが観測して、将来の選択結果が変わる可能性はあるが、選択アルゴリズムの変更はない。

`tests/fixtures/v203-late-duel.json` は変更前mainで採取した5日目の公開決闘決着直前の正規操作列と、変更前/決着後/確認後の状態SHA-256。旧版で全ハッシュが一致し、同じ入力の新旧戦闘はHP・勝敗・履歴・乱数が同一で、公開決闘FPだけ＋1差となることを検証する。

## バランス比較用データの取得可否

すべて既存のGameState/ログ/操作再生から取得可能。新しいログ機構は不要。

| 指標 | 既存の取得元 |
| --- | --- |
| 4日目終了FP（各魔女） | 初期FPは全員0。actor別のfpログのamountをday<=4で合計。4日目HO判定後の状態を操作列から再生して照合可能。 |
| 8日目終了FP（各魔女） | 完走時のplayers[].fp、result.ranking[].fp。第8日日次HO報酬を含む。finalComparisonはHO報酬前なので混同しない。 |
| 5〜8日目の公開決闘勝利数 | day5〜8、type=win、data.kind=publicのログをactor別に数える。fpログのkind=duelも勝利ごとに1件。FP増加量そのものを勝利数にしない。 |
| 4日目FP首位・最終FP首位 | 上記FPから全員の最大値を比較。同率首位は全員保持。 |
| 最終首席 | result.chiefs（卒業資格と同点時の日次HO達成数を反映済み）。単なるFP首位と区別。 |
| 長期HO達成状況 | 完走時のplayers[].longGoal.achieved、result.graduates。 |
| イベント成功/失敗 | type=eventResultのday、data.event、data.success。 |

既存scripts/simulate.tsのfpHistoryはday/player/delta/source、playersは最終FPと長期HO達成、chiefsは首席を含む。ただし現行のJSON/CSV出力にはイベントごとの成否一覧は含まれない。simulateの戻り値GameStateにはeventResultログがあるため、その既存ログを抽出すれば取得でき、新しいゲーム内ログは不要。今回、出力スクリプト自体は変更していない。旧新比較には、同じAI版のbrowser-2.0.3とbrowser-2.0.4を明示して既存simulate(seed, rulesVersion)を使用できる。既存の試遊方針は人間1席の代行操作＋NPC3人であり、4席同一AI条件の比較自体は今回実施していない。

崩壊で4日目または8日目へ到達しなかった試行は「未到達」として扱い、欠けた終了FPを推測で補わない。元のGameStateから取得不能な追加情報は見つかっていない。現行JSON/CSVだけで全指標が直接揃うわけではなく、イベント成否等は既存ログからの抽出が必要。
