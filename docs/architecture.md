# アーキテクチャ

## データと制御

Vue 3画面 → Pinia `act(action)` → JSONデータ境界 → 純粋TypeScript `dispatch` → 複製状態上でvalidate/reduce/log → 不変条件検査 → 状態置換・自動保存。拒否時は元状態を保持。UIから能力・所持・APを直接変更しません。

`dispatch` は渡された状態を変更しない純粋APIです。内部関数は複製済み状態を更新します。PRNG状態もGameStateに含め、`Math.random`、現在時刻、UI演出から乱数を消費しません。ログのseqは受理順を表し、再生に影響する壁時計は保存しません。

## 状態

`GameState` はルール版、初期設定、seed、PRNG状態・抽選数、日、phase、4人の状態、イベント山札と現在予約、予知候補と票、結界、戦闘・戦闘履歴、挑戦への返答待ち、取引、操作ログ、監査ログ、最終結果を含みます。

`Player` は公開能力・AP・FPと、本人秘密の所持個体、HO・対象・日別結果、固有魔法／次回使用日、永久／仮レシピ、最高FP、休息／呪詛、夜行動、命令を保持します。

各 `Item` のIDはゲーム内で一意。`lock` は `event` または `trade:ID`。完成薬と素材を同じ所有権・移動処理で扱います。能力予約はevent.reservationsに別途保持し、移転と能力納品時に下限を検証します。

## 情報境界

通常画面は公開ログと `audience` に本人0を含む通知だけを表示。公開ステータスは名前・AI表示・能力・FP・AP。本人以外のHO・所持・魔法・夜行動は通常表示しません。終局時のHO開示は所持開示とは分けます。

`aiView` は公開情報と本人の私有状態だけを構築。相手から渡すのはID・名前・公開能力・FP・APのみ。ルール適用時の在庫検証・報酬抽選はエンジンの役割であり、AIの候補生成に相手在庫を渡しません。戦闘AIは公開能力と自分の持込薬、対戦中のHP・ため状態を使います。相手の薬と確定前の手は候補選択に使いません。

開発者表示とJSONはローカル試験者向けの全状態です。サーバーによる秘匿・悪意あるクライアントへの防御は提供しません。

## 検証・配布

Vitestは純粋ドメイン、PlaywrightはChromiumで実画面操作。シミュレーションは通常のdispatchだけを呼び、イベント失敗や乱数を強制変更しません。Viteは相対baseなのでGitHub Pagesのリポジトリサブパスでも静的資産を参照できます。CIと公開承認付きPagesワークフローを分離しています。
