## 画面構成

タイトル → キャラクターメイク → 卒業課題確認 → 各日の今日の課題確認 → 公開行動メイン（2巡） → 共通イベント結果確認 → 固有魔法／必要時の予知投票 → 秘匿行動メイン → 秘匿決闘 → 夜結果／課題判定／1日のまとめ → 翌日の課題確認、または終了。

固有魔法・投票・夜結果の確定・課題判定は元の状態遷移を維持し、表示だけを整理した。課題確認や結果確認の操作はドメインActionを発行しない。AIが同じAction内で既に処理した割り込み結果は、課題確認・自分の行動結果の後に表示する。

- 公開行動は採集、研究、納品、購買部、魔女間取引、決闘の各画面へ遷移。秘匿行動も行動を選ぶと対象・レシピなどの確認画面へ進む。確定前のキャンセルは表示用の入力を捨てるだけで、AP・素材・乱数・操作ログを変更しない。
- 成功した行動は結果確認画面を表示。通常行動後も自動で手番終了はせず、既存どおり0AP操作を行ってから明示的に手番終了する。
- 研究は必要素材各1個と所持／使用可能数を表示。錬金は選択レシピの必要数、所持数と予約分を表示し、作成予定分を控除した既存の作成可能候補を使う。
- 右側の共通メニューは上が持ち物、下が課題。素材／薬、今日の課題／卒業課題の各2タブ。薬の効果も表示。課題は本人のものだけを参照する。
- 他プレイヤーのカードはアイコン、名前、攻撃・防御・洞察、素材と薬の合計数を表示。相手のFP・AP・能力Lv・所持内訳はカードに表示しない。既存の公開行動・公開納品の履歴は公開ルールに従う。ゲーム終了後の配布課題の開示、明示的な開発者モードとJSONの全状態保存は既存仕様を維持。
- 日数・フェーズ・残AP・名声、イベントの通算失敗数と3回で全員敗北する条件を表示。画面切り替えでページ先頭へスクロール。共通メニューと操作欄はPC・390px幅で重ならないように配置。

## 戦闘画面

対戦相手確認 → 行動選択 → 双方の行動公開 → 判定結果 → 次ラウンド／戦闘終了確認。判定は従来のreducerへ一度だけ委譲し、表示の「公開」「判定を見る」では乱数やゲーム状態を変更しない。

- stickyヘッダーに最大5R・双方HP・有効なためる強化を表示。連続ためる／第5Rのためるは選択不可と理由表示。
- 既存Roundの基礎値・出目・薬・警戒・消費したためる補正・次Rの強化・ダメージ・カウンター・HP前後を使用。比較理由の日本語説明は `src/ui/combatPresentation.ts` に分離し、計算処理は持たない。
- 攻撃同士の相互ダメージ、完全防御／カウンター、攻撃対ためるの無防備を説明する。HP0または5R終了、最終HPの比較による勝敗理由を表示。
- 公開勝利FPの前後、秘匿報酬処理に伴うアイテム合計・FPの前後を表示。人間参加の模擬戦も、元の処理が終了した履歴を表示用に保持し、確認まで画面を留める。通常の戦闘終了確認／秘匿報酬の処理順は維持。

## セーブ互換性

ゲームの保存形式2、`majoken-save-v2`、ルール識別 `browser-0.2.2+decisions-5` を維持。v0.2.2の正規セーブは操作ログ再生で検証して読み込む。v0.1領域は変更しない。

v0.2.3の課題確認済み・行動結果・戦闘表示段階は別の `majoken-ui-v023` に保存。JSON出力には任意のトップレベル `presentation` を付け、v0.2.2のドメイン読み込みはこれを無視できる。setup＋操作列が一致する場合だけ表示位置を復元する。古いJSONには表示メタデータがないため、その日の課題をもう一度確認し、戦闘中は対戦相手確認から再開するが、AP・進行・アイテム・判定は変わらない。未確定の行動入力は保存せず安全にキャンセルする。模擬戦履歴はインポートされた表示メタデータを信用せず、検証済みゲーム履歴から参照する。

## 報告された4件の調査

| 項目 | 再現・原因 | 対応・仕様との関係 |
| --- | --- | --- |
| 初日の薬納品 | 1日目にもNormalの「魔法薬の品質検査」（薬4個）が抽選される。全員が素材3個のみで開始し、公開行動中に錬金できず、夜の作成はイベント締切より後。自動テストで初日に抽選され、薬0/4で失敗することを確認 | **要仕様確認・未修正**。初日の抽選除外、錬金時期、初期薬などはいずれもルール変更のため実施しない |
| ためるの補正0表示 | ためたRの `chargeBonus` は過去から消費する補正なので0が正しい。生成した強化は `nextCharge` に入る。旧UIはこの区別が不明瞭 | 表示修正。生成Rは「ためる強化を生成」、次Rの有効値をヘッダーに明示し、消費Rの補正とは区別。計算式・1回消費は維持 |
| 休息中の襲撃撃退 | 休息は戦闘不能にする状態ではない。襲撃を受けた魔女も通常の攻撃／防御／ためるを選び、防御でカウンター可能。警戒専用の初回防御補正は休息には付かない | 現行ルールと整合。テストで休息中の防御カウンターを再現。休息の翌日報酬は決闘なし／その夜の全勝のみ。無抵抗にする変更は行わない |
| 研究崩壊 | 共通イベント通算3失敗で即時全員敗北。「研究所崩壊の危機」というイベント名自体が即敗北条件ではない。崩壊日は夜の処理・課題判定がない | 失敗の累計・3回の閾値・結果時のペナルティを明示。判定なし・報酬なしの既存表示を回帰検証 |

## 仕様確認が必要な事項

1. 初日の薬納品を抽選から除外するか。今回は未修正。
2. 幻惑の戦闘内トグル要求と既存仕様が異なる。既存では固有魔法フェーズで確定し、自分が仕掛けた秘匿決闘のランダムな1Rへ自動適用する。今回は固有魔法画面に「幻惑を使用する」の選択を置き、戦闘の行動選択には確定済み状態を変更不可のチェックで表示する。**戦闘中に発動を切り替える実装はルール変更になるため保留**。相手の幻惑予定Rは事前開示しない。
