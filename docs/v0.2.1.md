# v0.2.1 改修・仕様確定記録

更新：2026-10-30（Asia/Tokyo）。ブランチ `feat/browser-v0.2`、PR #1。mainへのマージ・Pages公開は行わない。

## 確認して確定した点

初回確認とPR #1再レビュー指示を反映し、以下を確定仕様とする。再レビュー4件の修正詳細は [review-v0.2.1.md](review-v0.2.1.md)。

1. 攻撃vsためるは防御値と比較せず `max(1, 攻撃判定値 - 3)` のダメージ。攻撃とためるの表示判定値が同値でも命中する。
2. 第1巡の予約上限は素材・薬の個体数と能力値1ポイントを合算して、各魔女につき現在予約1単位。取消でその枠が回復する。
3. ためるの基本強化値は洞察＋1D6。洞察薬の＋4は維持する。

v0.2の「ためる中も防御＋出目で受ける」「第1巡から1人がまとめて納品可能」という規則を今回の確定仕様で上書きする。完全防御、厳密な防御超過時だけのカウンター、攻撃同士の相互ダメージ、2巡・8日間・最大5Rは維持。

## 8項目の実装

| 項目 | 実装内容 |
| --- | --- |
| 手番・割り込み | 公開行動の第1巡／第2巡と手番の魔女を常時表示する固定帯を追加。取引は中央の確認ダイアログで保持し、背景をinertにして返答待ちの理由を明示。Escapeや外側クリックでは閉じない。キーボードフォーカスをダイアログ内に保持し、確認ボタンは画面内に固定。返答後に復帰する |
| 納品上限 | `reservationRoom` / `reservationUnits` をUI・AI・人間代行・予約検証で共有。第1巡は複数回の予約操作も合算して1、取消で回復。第2巡と最終納品確認は個人上限なし。イベント全体の必要数・能力下限・先着順・所有権ロック・公開終了時確定は維持 |
| AI公開行動 | 行動者・内容・結果を実行順の消えない履歴として表示。手番終了に残APを表示。自動進行は維持し、時間制限で流れる通知や自動で消える演出を使わず、読者のペースで履歴を確認できる |
| 秘匿決闘結果 | 人間が参加した秘匿決闘は勝利・敗北・引分すべて `done` の戦闘を保持。結果確認→本人のOK→勝者の報酬選択／処理の順序に統一。OK前の進行・報酬選択を拒否する。第三者は確認不可。AI同士は従来どおり自動解決 |
| 戦闘判定・左右 | ためるは無防備、強化は次Rの攻撃／防御／カウンターへ適用し次Rで消費。5R目は次R持越し0。仕掛けた魔女を左、受けた魔女を右に統一し、現在HP・各R・結果・履歴を共通 `CombatRounds` で表示 |
| フェーズ別表示 | イベント詳細は公開行動に表示し、決闘割り込み中には隠す。魔法・夜行動・戦闘は必要な操作を優先。終了後の公開操作履歴は折りたたみ、イベント条件は別の履歴から確認可能。結果フェーズで本人のFP・HO・研究／能力移転／能力納品・Lv変化を表示 |
| 能力Lv | 境界と効果を監査。現在Lv、次の能力値までの差、現在効果・解禁条件を表示。研究・能力移転の直前直後の比較からLv上昇ログを一度だけ記録し、再読込や表示再計算では追加しない |
| 日次HO | 既存の夜の判定器は維持し、読み取り専用の `dailyProgress` を追加。全24種に進捗、未達成／達成見込み／達成確定を表示。予約の見込みはイベントの充足・有効ルート・取消を反映。取引申請・不成立だけでは進めない。確定時は「日次HO達成！ FP+1」。本人以外のHOは表示しない |

戦闘中にFP閾値の任意レシピ選択待ちが重なる場合も、まず戦闘結果・報酬を処理する。人間代行の優先順とUIの選択欄を合わせ、戦闘中に不可能なunlock操作を実行しない。

## 能力Lvの監査

- 5以下Lv1、6〜8Lv2、9以上Lv3。境界関数は変更不要だった。
- 攻撃Lv：呪詛の減衰量1/2/3。通常攻撃判定へのLvの自動加算はしない。
- 防御Lv：警戒の初R防御補正1/2/3、休息成功時の翌日採集・研究補正1/2/3。無防備なためるに警戒補正は使わない。
- 洞察Lv：持込枠1/2/3。今回の戦闘薬はLv3でのみ作成・持込可能。ためるはLvでなく能力値そのもの＋出目＋薬補正。
- 5→6、8→9の単体テストと、5→6・次閾値・通知の重複防止のブラウザテストを追加。

## 日次HOの見込みの範囲

研究・薬作成／獲得・採集・取引・偵察・戦利品・休息・呪詛・警戒は実際に成立したログを使う。順序HOは採集→研究／夜錬金の順を維持。決闘参加・ラウンド被害・3R同手は進行中の本人戦闘も表示に使い、勝利HOは勝敗が決まるまで達成見込みにしない。

納品HO7と協力HO11は有効な予約・行動に加えてイベント条件が満たされている場合に見込みとする。予約だけあり成功条件がまだ不足なら未達成のまま、進捗と成功待ちの説明を表示する。予約取消・非採用ルート・イベント失敗で見込みを取り消す。ルート未確定の素材／能力予約も候補の進捗には数える。研究所崩壊で本日の最終判定がなければ「判定なし・報酬なし」で終了する。最終判定の成否は当日の日次履歴を正とする。見込みの表示でFPを付与しない。

## 保存互換性

ルール版は `browser-0.2.1+decisions-4`。形式版・状態版は2、保存先は引き続き `majoken-save-v2`。確認待ちの戦闘と確認済みフラグも保存・再生する。

ルールが変わるため、旧v0.2および修正前v0.2.1の操作列を新ルールで再生する互換性はない。異なるルール版のJSON・ブラウザ保存は版不一致で拒否し、自動変換はしない。旧保存は新規開始やJSON読込で明示的に新版を保存するまで書き換えない。v0.1の `majoken-save-v1` は削除・上書きしない。

## 納品機会の検証と再試遊事項

素材4個のイベントを使った比較テストでは、個人上限なしで1人が4個予約すると貢献者1人。第1巡1個制限では4人が各1個を予約でき、4人ともHO7の達成見込み・イベント成功時の貢献実績を得る。第1巡で枠が埋まること自体は残る。

再レビュー修正後の4seed試遊では、納品型イベントの各日の第1巡予約者数と成功貢献者数、およびHO7/11の成否を [simulation.json](reports/simulation.json) に追加記録。判定されたHO7/11は配布9件中8件達成、1件未達成。抽選イベントや所持適合素材による差も含むため、これを改修前との統計的な改善率とは扱わない。

未解決の実装不具合は検出していない。有人再試遊では、ダイアログの読みやすさ、強化防御を含む読み合い、必要素材を持たない後手の機会、第2巡の残枠の偏り、全HOの難度を確認する。AIは従来同様の検証用ヒューリスティックで、最適戦略を保証しない。
