# v2.1 Phase 1: rule identity and save foundation

New games use `browser-2.1` and `majoken-save-rules-2.1`. The JSON envelope remains `majoken-save`, version 2. The five existing UI-supported versions retain their identifiers, original slots, replay behavior and save validation. There is no migration or conversion. Resume searches v2.1 first, followed by the existing slots in their original order; explicit old-version resume remains available, including a new 2.0.4 resume button.

Phase 1 inherits current 2.0.4 behavior, including seeded tied-element AI and public-duel FP of +1 on days 1–4 and +2 on days 5–8. It does not claim complete v2.1 rules compliance. Automatic-win HO history, final-comparison FP timing, day-8 summary/result UI, HO disclosure, collapse/chief presentation and independent last-result storage remain for later phases. The unreproduced normal secret-win report is not patched speculatively.

The fixture `tests/fixtures/v21-legacy-replay.json` was generated before source changes at main `e6c99f1d63087b8ed908f57d4baa65c43aa6e7ae`. Each old version has a SHA-256 chain over its initial serialized state and every subsequent serialized state under the recorded setup and existing `simulationAction` policy. Tests compare this chain and final state hash, RNG/draw count, FP and long-HO results, then validate strict save replay. Historical combat-save fixtures and the original 2.0.4 secret-victory assertions are retained; the same normal-secret-victory scenario also runs under 2.1.

Deferred decisions remain: show a completed result even if independent result persistence fails, notify and retry the same finalized data without rerunning rules; do not migrate old completed saves into the new last-result record; use initial seat order without ranks for collapse. Independent result persistence is not implemented in this phase.

Validation: 541 unit tests passed, including five pre-change legacy state-chain comparisons (1,030 operations total), strict save replay, independent slots, failure/retry protection and v2.1 duel rewards for both winners on all eight days. The production build and type check passed. All 83 browser cases were verified: the initial full run passed 79; four test expectations still referring to the former new-game slot or a non-rendered error string were corrected, and all seven cases in the affected two files then passed. Browser coverage includes old-five-version explicit resume, v2.1 failure/retry, 2.1/2.0.4/2.0.3 late-duel FP and the original Nemu secret-win regression. Test profiles, caches, build output and reports were isolated under a unique temporary directory. Existing balance logs were not modified.
