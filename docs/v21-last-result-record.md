# フェーズ6：独立した最新終了結果

基準mainは cc0dc69396f3f389406a388f7956db956476a1a7。統合後CI 42762017115のsuccessを確認して開始。

## 実装前の保存設計

- 保存キーは `majoken-last-result-v1`。既存のルール別 `majoken-save-rules-*` とUI保存枠は変更しない。
- 外枠は `{format:"majoken-result",version:1,id,rulesVersion,presentation}`。既存ゲームのmajoken-save version 2とは別スキーマ。
- 全GameState保存は採用しない。秘密ログ、戦闘ラウンド、所持品、固有魔法、乱数状態、操作列を複製せず、終了画面が使用する確定済み表示データだけを保存する。
- presentationには終了日/理由、4人分の確定済み結末・順位・FP・日次成功数、長期HO説明/成否、判定済み日次HO内容/成否、第8日まとめ用の本人通知/持ち物差分/日次報酬、全員のFP明細があればその記録を保持する。
- 説明文は保存時のルール版で整形して固定する。スナップショット読込ではゲーム再生もHO/FP/順位再判定も行わない。スキーマと内容整合を検証し、不正・欠落データは拒否する。
- 実際の進行中→終了の遷移だけを記録対象にする。既存終了済みセーブのload/import/saveだけでは生成しない。旧5版を新たに終了させた場合は、その旧版の確定結果を記録する。旧終了データ一括走査・自動移行はしない。

## 書き込み順序と失敗

1. 既存ゲーム保存を先に成功させる。失敗時は従来のpending候補を保持し、結果保存を実行しない。
2. ゲーム保存成功後、同じ確定状態から表示専用スナップショットを1回作成し、独立キーへsetItemする。
3. 結果保存だけ失敗してもゲーム結果は表示する。旧結果を削除せず、同一候補のJSONと通知をメモリに保持し、明示的な再保存だけを行う。再試行はゲーム保存やゲームロジックを呼ばない。
4. 次の研究開始・タイトル復帰・結果閲覧では独立キーへ書き込まない。次の研究終了時に最新候補へ置き換える。

localStorage.setItemの失敗時に既存値を保持する性質を利用し、removeItemや複数段階の上書きは使わない。2つのキーを原子的に同時更新できないため、結果保存失敗後の未保存候補はメモリにのみ保持する。失敗中にページを閉じた場合は、既存の有効な前回結果と正常保存済みゲームが残る。終了済みセーブの自動取り込みは行わない。

## 閲覧と互換性

タイトル「記録」→「前回の結果」。記録なし時は選択不可、破損/読み込み失敗時も拒否・案内し元データを変更しない。
EndingScreensを表示専用スナップショットでも使えるようにし、閲覧専用時は新規研究ボタンを除去する。タイトルへ戻るだけで、ゲームstore.stateの読替え・再開・保存を行わない。
既存の進行中保存・厳密再生・版別キー・旧固定fixtureは維持。フェーズ1〜5開発途中v2.1の既知の制約は追加移行せず維持する。複数件履歴・手動削除・クラウド連携・Pages公開は対象外。PR作成後停止する。

## 実装した検証・表示モデル

`records/lastResult.ts` がスナップショット生成と検証、`stores/results.ts` が独立キーの読込/保存/同一候補再保存を担当する。ゲームstoreは従来の正常保存が成功した後だけこの記録storeを呼ぶ。結果保存だけの失敗をゲーム保存失敗として扱わない。

idは初期設定のハッシュ、ルール版、終了時revisionから作る識別補助情報。ID一致を理由に次の終了結果の更新を省略しない。保存スナップショットは元のGameStateへの参照を持たず、確定済み表示モデルをJSONコピーする。

スキーマは既知のフィールドのみを許可し、外枠/版/ルール、日、4人の一意ID、FP・順位・成功数、HO説明、日次履歴の欠落/重複、終了理由に応じた未判定・順位なし、内訳合計、表示順位ラベルなどの内部整合を確認する。ゲーム本体を結果スナップショットとして受け付けない。保存後の表示データを検証するもので、ゲームの再生や結果の再判定は行わない。

`ui/ending.ts` の `endingPresentation` でフェーズ5と同じ確定表示データを用意し、EndingScreensはGameStateまたは保存済み表示モデルを受け取る。前回結果の閲覧では後者だけを渡す。HO開閉・まとめ往復は同じ画面部品の表示状態だけで処理する。
閲覧中は進行中ゲームの保存/再開/JSON操作と通知を表示せず、ルール表示も記録側に統一する。新規研究ボタンはなく、タイトルへ戻るだけ。進行中の保存値と現在のゲームstoreは変えない。

## 既知の制約

結果保存失敗後、未保存候補はメモリに保持される。再試行前にページを閉じた場合、その未保存候補は失われる。ただし以前の有効な前回結果と、先に保存成功した終了ゲームは保持される。既存終了ゲームからの自動移行を防ぐため、再起動後にそれを自動で前回結果へ変換しない。失敗通知が出た場合はページを閉じる前に同一候補の保存を再試行できる。
フェーズ1〜5の開発途中v2.1セーブに関する既知の厳密再生制約は既存設計記録のとおり。今回、ゲーム保存の照合や形式は変更せず、新しいゲーム状態の互換性制約は追加しない。
