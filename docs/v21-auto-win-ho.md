# v2.1 フェーズ2：自動勝利・HO・秘匿通知

基点はmain `8eea8a3865b8b404dd5df3b0793e6324dbbe5e53`。正式仕様書v2.1（1110版）を基準とする。フェーズ3以降の比較FP・終了UI・終了結果保存には変更しない。

## 2A：履歴表現

`browser-2.1`だけ、夜の自動決着を処理するときに`win`ログを1件記録する。既存の`nextCombat`から通常戦闘と重複しないIDを採番し、`data`に`automatic: true`、`hasRounds: false`、`kind: secret`、`initiated: true`を残す。同じ日の同じ襲撃者・対象は1指定なので、この組で二重確定を防ぐ。記録自体は乱数・FP・所持品を変更しない。

`duelHistory`は、従来の`combatHistory`と新版の自動勝利ログから共通の読み取り用履歴を返す。`opponents`は当事者2人、`participants`は実績の対象者で、自動勝利では襲撃側1人だけ。`hasRounds`で実ラウンドの有無を識別する。同じIDを重複して集計しない。自動勝利用の`Combat`、HP、ラウンド、属性選択、持込薬は生成しない。

保存形式`majoken-save` version 2、保存状態型、既存履歴の形、通常決闘の記録処理は維持する。新しい必須保存フィールドはない。旧5版では新ログ・追加採番を行わない。

## 2C：当事者への通知

`automaticBattle`の個人通知に、襲撃側は対象名と自動勝利、休息側は襲撃者名・相手の自動勝利・休息失敗を表示する。各通知の宛先は本人だけ。共通`win`記録の宛先も当事者2人に限定する。

既存の宛先フィルタを通した本人宛て通知だけを「自動決着の結果」パネル・日誌・当日のまとめで確認できる。パネルは表示専用で、新しい判定や確認Actionを作らない。報酬の選択・移動は既存の登録順処理を維持する。同じ相手を襲った別人の通知文が同文になり得るため、秘匿性テストでは日誌のログIDと通知件数も確認する。

## 互換性と制約

旧5版の固定ハッシュ基準は変更しない。フェーズ1の「2.1と2.0.4がゲーム全体で同一」という一時的テストは、今回の新版ルールと両立しないため、公開行動から夜間入力までの継承確認へ限定した。旧5版の状態ハッシュ・乱数・FP・HO・保存再生テストは全て維持する。

開発途中のフェーズ1 `browser-2.1`セーブは、新しい実績・通知・説明ログによって厳密再生の照合に失敗する可能性がある。旧5版の互換保証とは区別する。自動移行、欠けた実績の補完、照合検証の緩和、失敗データの自動上書きは実装しない。実際の利用者セーブは調査・変更していない。

このフェーズで作った正規操作列の新版セーブでは、解決前後・報酬後・日次判定後の再開、進捗と乱数の一致、保存失敗時の確定候補保持・同一内容の再保存を確認する。テスト用ブラウザ・データ・出力は専用一時ディレクトリへ隔離する。
