## 動線と公開範囲

- 通常終了：既存の第8日判定が完了 → 第8日のまとめで停止 → 明示的な「最終結果へ」 → 全員の最終結果を一斉表示。
- 最終結果の「第8日のまとめを見る」で戻り、何度でも往復できる。自動発表・新規アニメーションは追加しない。
- 崩壊：既存の3回目失敗の確認ダイアログ → 「確認した」の既存eventAck → 最終結果へ直接。まとめ・往復ボタンは表示しない。
- 第1〜7日は既存のまとめ・次の日への動作を維持。v2.1の第8日判定前ボタンだけ「課題を判定して第8日のまとめへ」とし、旧版の進行中の文言は維持。

終了時には進行中ダッシュボードを丸ごと非表示にする。まとめの他領域から本人/他者の長期HO・進捗・結末・順位・終了ログが先に見えないようにする。開発者JSON表示も終了時には通常ダッシュボードとともに表示しない。既存の明示的なJSON保存は維持する。

## 第8日まとめの情報源

- 本人の日次HO成否：保存済み第8日dailyHistory。報酬は本人の確定済みFPログを参照し、存在しない成功報酬を作らない。
- 夜間記録：既存のvisibleToMeを再利用し、本人が当事者の許可された夜間通知種別だけを表示。第三者の秘密ログやラウンドを追加公開しない。
- 持ち物：本人の確定済みnightInventoryの種類別増減を「夜間」と明示して表示。記録がなければ「記録なし」。公開行動を含めた全日分の持ち物や不足記録を推測・再生しない。
- 全員のFP：day8FpBreakdownから開始・終了・差分・実明細を取得。記録されたreason/amountと関連IDを日本語化する。最終FPは保存済みresult.rankingから表示する。
- 内訳欠落は「記録なし」、空明細は「増減なし」。相殺した正負明細はそのまま並べる。旧セーブの内訳をFPログから再構成しない。

この画面はdailyReviewの再生処理を呼ばない。保存済み記録の参照のみで、表示のためのゲーム再判定も行わない。

## 最終結果とHO詳細

result.rankingのfp/rank/daily/graduated、result.chiefsをそのまま使用する。順位・首席をUIで再計算しない。首席→卒業→落第で並べ、保存済み順位が同じ場合と落第者内は開始時の席ID順。順位同値は「同率n位」、落第者は「順位なし」と表示する。首席なし・全員落第でも4人全員を表示する。

崩壊は全員「研究所崩壊」「順位なし」「長期HO：未判定」。崩壊時点FPと判定済み日次実績を表示し、崩壊当日の未記録HOは「未判定・報酬なし」。長期HOの古いboolean値を新たな達成/失敗判定に使わない。

初期状態は具体的なHO条件と日次履歴を閉じる。「HOを公開」「HOを閉じる」で同じ画面内に全員分の長期HO内容・成否と日次HO内容・成否を表示/非表示にする。崩壊でも長期内容と未判定、判定済み日次のみを表示する。
説明文は保存されたルール版に対応するgoalDescriptionを参照し、対象者の席番号を名前へ表示変換する。日次HOは元から指定対象を配布しない実装なので、保存済みIDと成否から内容を表示でき、過去の対象者を推測する処理は不要。

## 表示状態と保存・再開

通常終了の選択画面だけを既存のUI用保存枠 `majoken-ui-rules-*` のversion 1へ任意のendViewとして追加する。setup/actionsのキーが一致する場合だけ復元する。進行中と崩壊のUI保存項目は従来のまま。
ゲームのmajoken-save version 2・ルール別保存キーには画面選択やHO開閉を追加しない。UI保存失敗・メタデータ欠落・旧メタデータではまとめを既定とし、結果の先行公開を避ける。明示的に結果へ進んだ保存状態なら再開時も結果を表示する。
HO詳細の開閉はコンポーネント内だけに保持し、画面移動・再読込で閉じる。画面往復でdispatch・ゲーム再生・HO/FP/順位判定・乱数消費・操作ログ追加は行わない。既存のセーブ読込時の厳密再生検証は維持する。

保存失敗時のpending候補・再保存は既存storeのまま。保存前の結果を先行表示せず、同じ確定済み候補を保存後にまとめを表示する。過去のUIメタデータから終了時の不要なブリーフィング/行動結果を復元しない。

フェーズ1〜4の開発途中v2.1の既知の厳密再生制約は従来どおり。今回は表示だけなので新たなゲーム状態形式の互換性制約は追加しない。

独立した「前回の結果」保存、終了結果の最新1件管理、タイトル記録メニュー、過去結果一覧はフェーズ6以降。今回実装しない。Pagesの公開・設定・URLは変更しない。PR作成までで停止し、マージしない。
