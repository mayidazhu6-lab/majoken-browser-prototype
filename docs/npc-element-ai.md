# NPC属性選択の同点抽選（2026-11-06）

## 調査

PR #9統合済みmain `0f23770` を確認。正式作業フォルダの開始時の未コミット変更なし、origin/mainとの差分0/0。専用ブランチは `feature/npc-element-tiebreak`。別クローン・worktree作成なし。

正式仕様書v2.0のAI方針は、相手の3属性に対する与ダメージと被ダメージの差を評価し、同順位をシード付き乱数で選ぶ方針。`chooseElement`の評価式は各相手属性を等しく扱い、残HPを上限にした実ダメージ差を合計する。自分の属性Lvと持込薬、相手の公開能力、双方HPを使用し、相手の確定入力・薬の内訳は参照しない。

旧実装は `STATS = [attack, defense, insight]` をreduceし、厳密に大きい評価値にだけ更新するため、同点では先頭の火が残る。同じLv内の能力差はダメージに影響しない。例えば全属性Lv1では全評価0、水能力5でも同点、水能力6なら水の評価3、風能力9なら風の評価6。相手HP1でダメージが上限に達すると、水Lv2でも全属性同点になる。

同等条件・薬なし・HP12で `ai-audit-0`〜`ai-audit-99` を比較した標本は、従来版が火100/水0/風0、修正版が火37/水34/風29。これはこの固定標本の結果であり、実ゲームの属性使用率を均等に強制するものではない。

## 修正・承認済みの乱数影響

新規ゲームの `browser-2.0.3` だけ、最高評価が複数の場合に候補から既存PRNGの`pick`で等確率抽選する。最高評価が単独なら乱数を消費しない。評価式、属性相性、ダメージ、薬、夜間補正、KO・勝敗判定は変更しない。抽選理由・候補・結果は開発者専用の既存rngログに記録する。

同点のNPC1人の選択につき乱数を1回追加する。NPC同士なら1ラウンドで最大2回追加し、左→右の既存の呼出順を維持する。以後の抽選結果が従来版と変わり得ることを実装前に報告し、ユーザーの承認を得た。同一シード・同一状態・同一操作列の再現性は維持する。

## 保存互換性

保存形式はversion 2のまま。既存のrulesVersionでAIを分岐し、保存データへの新しい必須フィールドや自動変換は追加しない。v2.0.2以前のchooseElementは従来の固定優先順位と乱数非消費を維持し、再開後の新しいラウンドでも従来AIを使う。

新規ゲームは `majoken-save-rules-2.0.3`、旧v2.0.2は従来の `majoken-save-rules-2.0.2` を使用。旧v2.0・v2.0.1も元の枠を維持。「続きから」は最新の保存枠を優先し、旧v2.0.2は専用ボタンで明示的に再開できる。新規開始で旧保存枠を上書きしない。JSON読込も元の版と保存枠へ戻す。

`tests/fixtures/v202-combat-save.json` は変更前コードで生成した1ラウンド後の保存と、従来コードで戦闘終了・確認まで継続した状態のSHA-256。旧セーブの完全一致再生と、継続後の完全一致を確認するための固定データ。
