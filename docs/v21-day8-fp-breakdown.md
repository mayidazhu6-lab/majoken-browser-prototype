## FP変更経路の調査と記録方式

初期値設定を除くFP変更はすべて `core.fp()` に集約されている。ここで既存の下限0処理後の実増減を記録する。計算式、呼び出し回数、乱数、既存FPログの内容・順序・audienceは変更しない。本文や行動ログからの理由推測・再構成は行わない。

| 理由コード | 確定経路                                               | 付随情報                         |
| ---------- | ------------------------------------------------------ | -------------------------------- |
| `duel`     | `reducer.finishCombat` の通常公開決闘勝者への報酬      | 敗者ID                           |
| `event`    | `events.resolveEvent` の実際の報酬対象者               | イベントID                       |
| `scout`    | `night.finishNight` の実際に成功した偵察戦闘による減点 | その減点を発生させた偵察者ID一覧 |
| `ho`       | `reducer.evaluateHO` の日次HO成功報酬                  | HO条件・内容は含めない           |

`reducer.nightResults` にも旧ルール専用の偵察減点呼び出しがあるが、v2.1では `finishNight` が使われる。旧版の当該呼び出し・挙動は変更していない。秘匿襲撃・自動勝利・模擬戦自体ではFP報酬を作らない。長期HO達成にも追加FPを作らない。

複数偵察は既存どおり対象者ごとに集約減点する。関連IDは実際に戦闘に勝って減点対象を発生させた処理から取得する。下限0で減点量が切り詰められる場合は要求値ではなく実減点量を保存する。実増減0の呼び出しは増減明細を作らない。

## データ構造と期間

`GameState.day8Fp?` を任意フィールドとして追加。保存の外枠は `majoken-save` version 2、ルール識別子と保存キーはそのまま。

- `day: 8`
- `start: {player, fp}[]`：実際に第8日へ入る瞬間の4人分のFP。第7日日次HO報酬は反映済み、第8日の公開行動前。
- `entries: {order, day, player, amount, reason, fpAfter, relatedPlayers?, eventId?}[]`
  - `order` は全員共通の確定順。`amount` は符号付き実増減、`fpAfter` はその変更直後の確定FP。
  - 理由は安定した内部コードで、表示文言を保存しない。
- `final?: {player, fp}[]`：通常終了または第8日崩壊時の実FP。終了解決時に一度だけ固定する。

第1〜7日は新規記録フィールドを作らない。開始時の記録がなければ途中から推測して初期化しない。`beginDay8Fp` は実際の `nextDay` 遷移だけが呼び、ロード・画面参照は呼ばない。

## 終了後参照と秘匿性

`day8FpBreakdown()` は終了状態のみを対象に、4人分の開始FP・終了FP・差分と、その人のFP明細を返す。すべてコピーし、返却値の変更が保存状態を変えないようにする。

返却情報は上記FP項目の許可リストのみ。秘密ログ全文、夜間行動一覧、決闘ラウンド、所持品、固有魔法、長期HO条件・成否を含めない。偵察者などの関連IDはQ62のFP増減理由としてのみ利用する。既存ゲーム中UIにはこの参照関数を接続せず、既存ログの秘匿範囲も変えない。

- 記録欠落：`undefined`。「記録なし」にできる。
- 記録あり・明細なし：4人分の値と空配列。「増減なし」にできる。
- 合計0でも実増減があった場合：正負の明細を維持する。

崩壊時も既に確定した第8日記録を保持するが、崩壊に第8日まとめ画面を新設する意味ではない。第1〜7日崩壊では第8日記録自体がない。崩壊後のHO・行動・架空の増減は作らない。

## 保存互換性・二重記録防止

旧5版にはフィールドを追加せず、固定1,030操作fixtureを変更しない。内訳がない旧版セーブはそのまま厳密再生でき、内訳欠落を破損として扱わない。ログから内訳を復元しない。

フェーズ1〜3の開発途中 `browser-2.1` セーブには引き続き厳密再生制約がある。今回の追加影響は **第8日進行中・終了済み・第8日崩壊のセーブ**。再生では新フィールドが作られるため、欠落する旧開発データとは一致しない。第1〜7日のデータは今回の追加フィールドによる不一致を生じないが、過去フェーズの変更由来の制約は残る。データの自動移行・削除・上書きも、照合の緩和も行わない。不一致時に元データへ書き込まないことをテストする。

開始・終了スナップショットは既存時に再作成しない。明細は既存のFP変更1回につき1回だけ追加する。同じ確定操作の重複は既存フェーズガードで拒否する。表示の参照は読み取り専用。保存失敗時には既存storeの確定済みpending候補をそのまま保存し、FP・HO・乱数・明細を再実行しない。persistence/storeは変更しない。
